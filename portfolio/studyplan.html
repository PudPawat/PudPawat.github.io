The Profile

Pawat Chunhachatrachai · 孫瓦德 · PhD student, GINM, National Taiwan University.

Pawat Chunhachatrachai is a PhD student at the Graduate Institute of Networking and Multimedia (GINM), National Taiwan University, researching at CMLAB under Prof. Winston H. Hsu. His work sits at the intersection of 3D scene understanding, embodied AI, and spatial reasoning — asking how machines can generate, render, and reason about the three-dimensional worlds that robots will one day learn in.

The route there was unusually hands-on. Trained as a mechanical engineer at King Mongkut's University of Technology Thonburi (with an exchange at Shibaura Institute of Technology, Japan), he moved to Taiwan for an MSc in Mechanical Engineering with a focus on AI & Machine Learning at NTUST — while simultaneously working as an AI engineer at SINBON Electronics, where his force-control algorithm for electrically assisted bicycles was patented in Europe and Taiwan.

Years of industrial computer vision — contact-lens defect detection, automated optical inspection, OCR pipelines, low-code tooling for factory engineers — taught him that a system is only as good as its validation. That conviction now anchors his doctoral research program: generate-and-validate, where generative models propose scenes, tasks, and plans, and dedicated validators — physics checks, spatial reasoning, VLM critics — verify them before a robot ever trains on them.

“The unifying paradigm is generate-and-validate: generative models propose scenes, tasks, and plans; validation modules verify them.”

He has presented at CVPR 2026 (2nd Workshop on 3D-LLM/VLA, Denver), made academic visits to UC Berkeley, NVIDIA, and Google, taught three graduate courses as an invited lecturer at KMUTT, and served as Vice President of the Thai Student Association at NTUST. He holds 10+ Google Cloud certifications.

No. 01 Lead Feature · Spatial Reasoning 2nd Workshop on 3D-LLM/VLA · CVPR 2026 · Denver, USA · arXiv:2605.18209

SpatioRoute — Dynamic Prompt Routing for Zero-Shot Spatial Reasoning

When and how a model reasons should adapt to the question — not the other way around.

+5%
Accuracy over fixed-prompt baselines on SQA3D, across multiple VLM families
0
Fine-tuning, 3D sensors, or point-cloud inputs required — zero-shot, video-only
2
Routing modes — rule-based (SpatioRoute-R) and LLM-driven (SpatioRoute-L)

Spatial question answering over egocentric video asks vision-language models to reason about 3D positions, scene affordances, and directional relationships — zero-shot, with no task-specific training. Existing pipelines apply one fixed prompt to every question, regardless of whether it asks about direction, distance, counting, or affordance.

SpatioRoute replaces the fixed prompt with a router: each question is mapped to a semantically tailored prompt before VLM inference. SpatioRoute-R deterministically maps SQA3D question typologies to specialized templates; SpatioRoute-L uses a small text LLM with few-shot demonstrations — video-free at routing time, so the routing step adds almost no cost.

The headline finding is that question-aware routing beats uniform reasoning: uniform Chain-of-Thought prompting can actually degrade spatial VQA on Qwen-family VLMs. Across multiple VLM families on SQA3D, SpatioRoute improves accuracy by up to 5% — a strong state of the art for zero-shot, video-only spatial VQA without 3D point-cloud input.

The insight carries directly into the doctoral study plan on reasoning for robotics: a robot, like a VLM, must decide when to think and when to act — and adaptive reasoning is what makes that decision tractable.

Co-authors: G. J. Faure · H.-T. Su · W. H. Hsu.

No. 02 Embodied Scene Generation · Part 1 Qwen2.5-VL · Objaverse · ABO

Auto Labeling & Captioning for 3D Objects

Turning raw meshes into a retrieval-ready object library — the asset foundation every downstream scene is built on.

VLM captioningMulti-view renderingSemantic orientationPlacement affordancesSQLite + JSONLHuman-verification UI

Objaverse and ABO meshes ship with thin product text — not enough for language-driven retrieval and placement. This pipeline turns raw meshes into a retrieval-ready object library: six axis-aligned multi-view renders per mesh feed structured VLM captioning (Qwen2.5-VL), producing rich, queryable descriptions of every asset.

Beyond captions, each object gets semantic orientation — front and up axes with confidence scores — so a chair knows which way it faces before it is ever placed in a room.

The pipeline also predicts placement affordances (wall-side vs. open-space vs. floor) and physical attributes — metric size, weight, material — the facts a physics-consistent scene composer needs. Everything is merged into a unified object database (SQLite + JSONL) behind a human-verification UI, keeping a person in the loop where VLM output needs checking.

This library is the substrate for text-to-scene generation (Feature No. 03) and, ultimately, for task-aware world generation in the PhD study plan.

No. 03 Embodied Scene Generation · Part 2 Three.js CAD · MCP / REST agent tools

Text-to-Scene Generation from a 3D Object Library

Say “bedroom” — get a furnished, editable, agent-ready 3D room.

LLM plannerCaption-aware retrievalPose composerScene JSONIncremental edit APIBrowser CAD

On top of the labeled library sits a browser CAD for indoor architecture and a text-to-scene agent in three stages: a planner extracts furniture, placements, and spatial relations from natural language; a caption-aware retriever selects matching meshes from the object database; and a composer solves poses and emits Scene JSON for the CAD editor.

Sparse prompts like “bedroom” expand through room presets; rich spatial language is followed directly — the system meets the user at whatever level of detail they bring.

Crucially, generation is not one-shot. An incremental edit API — “add a table at the corner” — modifies an existing scene without regenerating walls or prior furniture, which is exactly the mechanism curricula for robot learning will need: worlds that change a little at a time.

The whole system is exposed as MCP / REST tools, so LLM agents can build and edit scenes programmatically — 2D/3D plan views, live Scene JSON, and an object library, all in the browser.

No. 04 Hybrid Rendering · WebGL SuperSplat extension · Live demo · ~62 FPS

Reflective Mesh Compositing in 3DGS Scenes

One scene, two paradigms — a glossy mesh sits inside a Gaussian-splat world and reflects it.

~62 fps
Interactive browser rates — 120k-polygon car on a laptop GPU
2
Rendering paradigms unified — splat rasterization + ray operations on meshes
360°
Reflection-probe fallback — the splat world captured as prefiltered cubemaps

3D Gaussian Splatting produces photorealistic environments — but splats yield no triangles and no G-buffer, so standard reflection APIs simply cannot make a mesh object reflect the splat world around it. This system solves that by combining two rendering paradigms in a single WebGL canvas.

The 3DGS environment is drawn by splat rasterization, while reflections on mesh objects are computed by ray operations: screen-space ray marching against a combined splat + mesh depth buffer, with reflection probes capturing the splat world as prefiltered cubemaps for 360° fallback when rays exit the screen.

A confidence-weighted blend unifies both paths, so a glossy GLB object sits inside the splat scene and convincingly reflects it — something neither pipeline can do alone. The system runs in the browser at interactive rates and extends the open-source SuperSplat viewer.

For the research program, this is the appearance engine: photorealistic robot simulation needs environments that look real and objects that interact with light believably — this hybrid renderer is a key building block toward both.
